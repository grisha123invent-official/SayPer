## Раскладка исходников

Идентификатор приложения и папка исходников остались прежними
(`com.grisha.nadiktovka`, `Sources/Nadiktovka`): к идентификатору привязаны
разрешения на клавиатуру, автозапуск и запись в связке ключей — смена сбросила бы
всё это. Пользователь идентификатора не видит, поэтому менять его смысла нет.

`build.sh` обходит дерево `Sources/Nadiktovka` целиком, так что новый файл
достаточно положить в нужную папку.

| Файл | Что делает |
|---|---|
| `Core/AppDelegate.swift` | состояния, оркестровка записи, склейка всего вместе |
| `Core/Settings.swift` | настройки в UserDefaults и типизированный доступ к ним |
| `Core/AppEvents.swift` | `TranscriptionRecord` и шина, по которой уходит готовая расшифровка |
| `Core/AppPaths.swift` | папка `~/Library/Application Support/SayPer` |
| `Core/AppInfo.swift` | версия сборки для диагностики |
| `Core/Keychain.swift` | хранение API-ключа |
| `Core/LaunchAtLogin.swift` | автозапуск через `SMAppService` |
| `Core/Sounds.swift` | звуковые сигналы и их настройки |
| `Hotkey/HotkeyMonitor.swift` | глобальное отслеживание нажатия/отпускания модификатора |
| `Audio/AudioRecorder.swift` | AVAudioEngine → 16 kHz mono AAC + уровень громкости |
| `Audio/Transcriber.swift` | `/v1/audio/transcriptions` и необязательная чистка текста |
| `Audio/TextInserter.swift` | ⌘V через CGEvent либо посимвольный ввод юникода |
| `Audio/OutputDucker.swift` | приглушение звука компьютера на время записи |
| `UI/RecordingIndicator.swift` | плавающая пилюля со стеклом, эквалайзером и искрами по кромке |
| `UI/DesignSystem.swift` | токены и общие кирпичики окна настроек |
| `UI/SettingsRootView.swift` | окно настроек: полоса разделов и панель раздела |
| `UI/Sections/` | по файлу на раздел настроек |
| `Features/Onboarding/` | мастер первого запуска |
| `Features/Recording/RecordingGate.swift` | режим активации: события хоткея → команды записи |
| `Features/StatusMenu/StatusPanel.swift` | панель в строке статуса |
| `Features/History/HistoryStore.swift` | последние расшифровки |
| `Features/Usage/UsageStore.swift` | минуты, слова и оценка стоимости |
| `Tools/MakeIcon.swift` | генерация иконки в `.iconset` при сборке |
| `Tools/MakeDMGBackground.swift` | фон окна установки |

Запись идёт во временный файл и удаляется сразу после расшифровки.

## Два вида стекла

В приложении два разных механизма стекла, и они не взаимозаменяемы.

**Внутри окна** — `glassEffect` из SwiftUI. Он преломляет то, что нарисовано
под ним в том же окне: фон-орб, соседние карточки. Так сделаны панель раздела,
переключатели и капсула активной вкладки.

**В прозрачных окнах** — `NSGlassEffectView` из AppKit (`Features/StatusMenu`,
`UI/RecordingIndicator`). У пилюли и панели строки меню под стеклом нет ничего
своего, преломлять надо фон чужого приложения. SwiftUI-стекло в такой ситуации
преломляет пустоту и выдаёт серую плашку.

У прозрачного стиля есть цена: над белым документом стекло остаётся белым,
и светлая подпись на нём пропадает. Поэтому под капсулой пилюли лежит тёмная
подложка — она под стеклом, стекло преломляет её вместе с фоном.

## Сеть

Каждая отправка записи идёт по своей `URLSession`, которая сразу закрывается.
Причина в журнале была видна прямо: первая отправка после запуска — полторы
секунды, следующая через 20-40 секунд — ровно 60 секунд тишины, обрыв
по таймауту и мгновенный успех на повторе. Приложение живёт в фоне, система его
придерживает, и сокет из пула к моменту второй отправки уже мёртв — URLSession
об этом не знает и пишет в пустоту до таймаута.

У запроса задан собственный `timeoutInterval`. Без него действует умолчание
`URLRequest` в 60 секунд, и настройка сессии не значит ничего: таймаут запроса
её перекрывает.

## Подпись и разрешения

macOS привязывает «Универсальный доступ» к подписи приложения. При подписи
**ad-hoc** отпечаток меняется с каждой сборкой, поэтому разрешение молча
перестаёт действовать: галочка в списке стоит, а доступа нет.

Поэтому сборка использует постоянный самоподписанный сертификат
**«Nadiktovka Dev»** из связки ключей — имя осталось от прежнего названия
приложения и менять его нельзя: к нему привязаны выданные разрешения.
С ним требование подписи выглядит так:

```
identifier "com.grisha.nadiktovka" and certificate leaf = H"9e7252…"
```

Хеша сборки здесь нет — значит разрешение переживает пересборки.

**Сертификат надо беречь.** Он есть только в связке ключей той машины, где его
завели. Если он пропадёт, у всех, кто уже поставил приложение, при следующем
обновлении слетят «Универсальный доступ» и «Мониторинг ввода» — и восстановить
это будет нечем. Резервная копия:

```bash
security export -k ~/Library/Keychains/login.keychain-db \
  -t identities -f pkcs12 -o ~/SayPer-signing-cert.p12
```

Пароль на архив спросят интерактивно. Файл — не в репозиторий.

Если сертификата нет и восстанавливать нечего, создать заново:

```bash
openssl req -x509 -newkey rsa:2048 -keyout key.pem -out cert.pem -days 3650 -nodes \
  -subj "/CN=Nadiktovka Dev" \
  -addext "extendedKeyUsage=critical,codeSigning" \
  -addext "basicConstraints=critical,CA:false" \
  -addext "keyUsage=critical,digitalSignature"
openssl pkcs12 -export -out cert.p12 -inkey key.pem -in cert.pem -passout pass:nadiktovka \
  -keypbe PBE-SHA1-3DES -certpbe PBE-SHA1-3DES -macalg sha1
security import cert.p12 -k ~/Library/Keychains/login.keychain-db -P nadiktovka -T /usr/bin/codesign -A
rm key.pem cert.p12
```

Новый сертификат — новое требование подписи, то есть у всех пользователей
разрешения слетят один раз.

`build.sh` подхватывает сертификат сам. Он числится недоверенным
(`CSSMERR_TP_NOT_TRUSTED`) — для локальной подписи это нормально и работе
не мешает. Без сертификата скрипт откатывается на ad-hoc и сам сбрасывает
мёртвую запись разрешения, чтобы её можно было выдать заново.

## Выпуск версии

### 1. Версия

В `Resources/Info.plist` два поля, и они про разное:

| Ключ | Что это | Пример |
|---|---|---|
| `CFBundleShortVersionString` | видит человек | `1.0-beta.1` → `1.0-beta.2` → `1.0` |
| `CFBundleVersion` | счётчик сборок, только вверх | `1`, `2`, `3` |

Версия показывается в «Диагностике»: без неё на любой жалобе пришлось бы
гадать, какая у человека сборка.

### 2. Образ

```bash
./build.sh dmg          # → dist/SayPer-<версия>.dmg
```

Скрипт соберёт приложение, нарисует фон окна установки, положит рядом ссылку
на «Программы» и расставит иконки. Координаты иконок дублируются в
`Tools/MakeDMGBackground.swift` и в `build.sh` — правятся только вместе,
иначе стрелка на фоне разъедется с настоящими значками.

### 3. Проверка

Смонтировать, перетащить в «Программы», запустить. Заодно убедиться, что
подпись цела:

```bash
codesign --verify --deep --strict --verbose=2 /Volumes/SayPer/SayPer.app
# satisfies its Designated Requirement — разрешения переживут обновление

spctl --assess --type execute -vv /Volumes/SayPer/SayPer.app
# rejected — так и должно быть: приложение не заверено Apple
```

Первая проверка важнее второй. Если подпись перестала удовлетворять своему
требованию, у всех, кто уже поставил приложение, при обновлении слетят
«Универсальный доступ» и «Мониторинг ввода».

### 4. Публикация

```bash
git push
gh release create v<версия> dist/SayPer-<версия>.dmg \
    --title "SayPer <версия>" --prerelease --notes "…"
```

Образ прикрепляется к релизу, а не коммитится: `dist/` в `.gitignore`.
Бинарник в истории git остался бы там навсегда, и каждая версия раздувала бы
клон на полтора мегабайта.

## Если что-то не работает

Панель в строке статуса → **«Диагностика…»**. Там видно версию сборки,
состояние перехвата клавиатуры, микрофона, ключа и текущий хоткей.
Подробности пишутся в журнал:

```bash
tail -f ~/Library/Logs/SayPer.log
```
